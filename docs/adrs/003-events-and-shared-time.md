# 003: Note events and a shared transition clock

Expand each native song into a bounded, ordered list of typed note events in `LowlightPlanning`. Event algorithm/format version 1 uses the existing SplitMix64 generator, seeded by the song's take seed. Encoded native records carry `formatVersion`; decoding also accepts the original unversioned records from the v1 fixture envelope, while rejecting unknown versions. Preserve the accepted emission order, gesture deduplication, repeated-pitch damping, monophonic bass damping, and incompatible-chord releases. Quantize absolute onset, gate, and release endpoints only after damping, using nearest-even rounding at the canonical 32 kHz rate. These endpoints describe envelopes; percussion sample tails still require explicit rack-level handling.

Adjacent songs reuse the same immutable transition: a common-tone pivot and a four-bar linear BPM ramp. Integrate that ramp into seconds before rounding absolute frames. Both songs therefore name exactly the same frames throughout their shared 16 beats, including 60↔100 BPM changes. Small expressive offsets retain the reference's beat conversion using the song tempo before clock integration. Beyond the form, note gates follow the successor tempo.

The pivot uses the intersection of both scales, avoids neighboring semitones, and retains the reference's ordered root/tone scoring and register placement. Outgoing and incoming dry guitar/piano (and air) gains are complementary and linear in elapsed time. Gain evaluation uses quantized ramp endpoints, within one canonical frame of the continuous reference. Apply this envelope before compression and room processing; wet tails need their own continuing DSP state. Rhythm hands off at beat 8: the outgoing rack fades over the preceding 75 ms, and the incoming rack becomes active at that shared frame. Suppressing note-ons alone would leave overlapping one-shot tails.

Preparation runs off the future audio callback. Each song has at most 44 bars; a conservative 28 emissions per bar remains below the 2,048-event capacity. The timeline retains one issued schedule and one pending song, bounded histories, a canonical position, and generator state. Checkpoints restore musical intent and the planning cursor. They do not restore two active racks, decoders, effects, or a sounding playhead. Future transport must restore gracefully after the user presses Play and must not autoplay on launch.

The existing v9 event fixture has a separate validated import path that bypasses native song validation and RNG. This preserves its hand-authored baseline melody for later DSP comparisons. Three additional complete event scores were generated independently through the frozen Python algorithm with a separate SplitMix adapter; Swift did not produce their expected values. The manifest freezes source/fixture hashes and predeclared tolerances of one canonical frame for endpoints and 1e-12 for scalar metadata. `verify-events.py` rederives and compares without overwriting an existing oracle.

This change specifies scheduling and envelopes without implementing audible playback. A 64-voice engine, deterministic stealing, decoded one-shot lifetimes, actual overlap/memory bounds, and aligned audio comparisons remain DSP work. The handwritten review-budget exception keeps event expansion and its shared-clock invariant together, including independent reference tooling and tests; it adds no UI or sound retuning.
