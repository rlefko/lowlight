# Engine configuration recovery

`SessionPlayback` now observes configuration changes for its current audio engine. A notification only updates the bounded mailbox; all graph mutation and final release remain on the existing serial control queue. Engine identities reject late notifications from an owner that has already been disposed. Registration is followed by a current-format check before the first start, covering a hardware change between construction and observation.

An eligible recovery pauses the retained owner, reasserts the audio-session policy, and reconnects its source to the main mixer using the current output rate. The same worker, source node, render endpoint, and canonical musical cursor survive. The source stays at 32 kHz; the main mixer continues to track the device output automatically. This follows Apple's [configuration-change contract](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/avaudioengineconfigurationchange) and [main-mixer behavior](https://developer.apple.com/documentation/avfaudio/avaudioengine/mainmixernode).

Configuration changes never create a new Play request. User Pause, an interruption, or output disconnection defers reconnection until playback is authorized again. Generation checks after activation and reconnect reject superseded work. An unavailable output leaves the owner paused and reports a latched failure; only a new explicit Play retries it. Activation and engine-start failures retain their existing terminal cleanup behavior. Stop removes the observation before disposing the graph.

Reconnection may discard audio already prefetched by the old converter. Preserving the generated canonical cursor does not promise a continuous audible waveform across a physical route change. Media-services loss/reset is a separate lifecycle event and must recreate invalidated system audio objects.

Real offline tests cover unchanged source/worker identity, exact 50,003-frame continuation at the canonical rate, 32/44.1/48 kHz format changes, exact continuation from the observed canonical cursor after returning to 32 kHz, finite output and EOF, deferred recovery, coalesced notifications, unavailable-output retry, activation races, and stale engine notifications. The iOS integration test exercises the same configuration notification and retained graph alongside the real audio-session adapter.

The configuration-recovery commit passed all 130 audio tests in 38 suites in Debug and Release, 48 focused Thread Sanitizer tests in 11 suites, ten iOS integration tests and the launch UI test, and the unsigned iOS Release build. Formatting, repository checks, and all 13 CodeQL coverage-guard tests passed. All 193 deterministic exports (161 PCM and 32 JSON) remain byte-identical to PR #47; original-reference comparisons were not rerun locally. These are local software checks, not physical-device route or background certification.
