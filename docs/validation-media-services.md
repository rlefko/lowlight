# Media-services recovery

The playback coordinator observes media-services loss and reset through its existing audio-session observation. Both events invalidate in-flight startup, revoke automatic playback, and release orphaned engine objects on the serial control queue. Session observers remain installed so a loss can be followed by reset. Reset alone does not activate or resume audio; a fresh explicit Play is required, following Apple's [media-services recovery guidance](https://developer.apple.com/library/archive/qa/qa1749/_index.html).

Each activation cleanup obligation is tagged with its media-services generation. An activation admitted before a loss/reset cannot deactivate the replacement server when it eventually returns. A reset during an already-admitted deactivation also discards that obsolete result, including when Stop is still cleaning up. Completed terminal cleanup rejects captured late notifications. Existing genuine playback failures remain observable; an invalidated cleanup obligation is not described as successful deactivation.

`mediaServicesAvailable` is false after loss and true after reset. Play while services are unavailable cannot prepare or activate output, and the subsequent reset still requires a newer Play. Interruption ends, configuration notifications, refresh, and preparation retry cannot turn a reset into automatic playback. The coordinator retains final canonical position diagnostics; rebuilding through its existing factory alone does not reconstruct the old DSP history. Musical restoration is a separate transport contract.

Five real-engine test groups cover loss, reset without a preceding loss, playing and paused reset, immediate startup cancellation, blocked activation and terminal cleanup, failure preservation, fresh explicit recovery, and stale callbacks. The iOS adapter test verifies both system notification names and observer filtering/removal. Physical media-server reset and subsequent hardware playback remain device validation gates.

This increment passed all 135 audio tests in 39 suites in both Debug and Release, 53 focused Thread Sanitizer tests in 12 suites without warnings, 10 iOS tests and the UI smoke test, and the Release app build. Repository, formatting, lint, and 13 CodeQL coverage-guard tests passed. All 193 preserved PCM/scalar exports remained byte-identical to the accepted PR47 manifest; the original reference comparisons were not rerun for these coordinator-only changes.
