# Session audio source

`SessionAudioSource(worker:)` connects a prepared session to an `AVAudioSourceNode`. Construct the worker and source off the main and audio threads, then attach the node to an engine. The source claims the worker's single render endpoint; it cannot share that consumer with a separate offline render loop.

The render block always supplies 32 kHz, interleaved Float32 stereo. Apple's [fixed-format source initializer](https://developer.apple.com/documentation/avfaudio/avaudiosourcenode/init(format:renderblock:)) supports conversion to a different PCM sample rate, bit depth, or interleaving at the output connection. The bridge does not introduce another renderer, sample cache, resampler, or audio queue. The host chooses a supported stereo connection format and configures the engine outside the callback.

Each positive-size callback validates the supplied buffer layout and capacity, makes one native pull, and publishes a bounded atomic status. There is no preparation, lock, wait, retry, allocation, logging, or owner reclamation in that path. Invalid layouts clear their advertised writable storage, return a parameter error, and latch failure without advancing music. Buffer pointers and the declared buffer-list allocation must be valid; raw Core Audio storage is a caller responsibility. Zero-frame requests leave samples, status, and the musical cursor unchanged.

A late successor produces zero-filled unused output and `waitingForPreparation`. Musical time freezes at the missing onset while the device can continue consuming silence; the host must respond to sustained waiting or a worker failure. EOF becomes `finished`; a failed renderer becomes `failed` with silence. Status is the most recent source pull, and `position` counts generated canonical frames. Neither is an audible device playhead, and independent atomic reads are not one transactional snapshot.

The node's block retains both the endpoint and preparation worker even if the Swift wrapper is released. The host must stop and quiesce the engine consumer, request and join preparation shutdown, then detach and release the node off the callback. Worker shutdown alone does not prove callback quiescence. The bridge neither owns an engine nor activates an audio session.

The callback accesses the imported C buffer layout directly, avoiding runtime metadata helpers from Swift's audio-buffer-list collection wrapper. Swift's generated block thunk performs balanced retain/release operations on a context that the node keeps alive. This is not a zero-reference-counting claim: stable graph ownership prevents final context or owner destruction inside the callback.

Tests use Apple's [offline manual rendering mode](https://developer.apple.com/documentation/avfaudio/performing-offline-audio-processing), which disconnects the graph from audio hardware. At 32 kHz, real graph output matches the existing independent song sum, fades, and protection sample-for-sample across irregular pulls. Separate 44.1/48 kHz checks cover finite stereo output, device-frame duration, channel ordering, and drained silence. A held successor proves device time can advance through silence while the musical cursor freezes, followed by exact logical continuation. Boundary tests cover zero-frame calls, malformed and planar buffers with guarded storage, failure latching, and retained-node lifetimes.

Local validation on the pinned Xcode 26.6 toolchain passes all 97 audio tests in 31 suites in both Debug and Release; the six new tests also pass under ThreadSanitizer with sequential test scheduling and their actual concurrent worker roles intact. Nine iOS integration tests, one UI launch test, and the unsigned Release iPhone build pass. The iOS test awaits blocking worker startup on an explicit default-QoS queue; the final run has no startup priority-inversion diagnostic. Formatting, lint, repository checks, and 13 extraction-guard tests pass.

All 193 existing audio exports match the accepted PR #40 bytes. All 14 existing reference comparisons pass on those same inputs, with unchanged reference code, fixtures, and bank. Optimized ARM64 inspection confirms direct buffer access and lock-free 32-bit status operations, with no allocation, metadata lookup, or ARC calls in the callback body; the generated block thunk has the balanced ARC operations described above. This inspection covers the project callback and native render chain, not Apple's internal engine implementation. Hosted checks remain a separate required merge gate.

An [engine lifecycle owner](validation-audio-engine.md) now handles graph controls and ordered cleanup. Playback intent, interruptions/routes, background playback, lock-screen controls, and user-initiated checkpoint restoration remain separate work. Conversion smoke tests do not establish physical-device latency, converter cost, battery behavior, or locked-screen reliability.
