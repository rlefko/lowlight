# Playback audio-session lifecycle

The public `SessionPlayback` entry point now owns the iOS audio-session lifecycle on its existing serial control queue. Initialization stays silent and performs no session calls. Explicit Play prepares the worker first, then configures and activates the session before constructing the device graph and reading its output format. The main actor and audio callback never perform these blocking system calls.

The iOS adapter uses the [playback category](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback), default mode, and no category options. It requests no microphone access, mixing, ducking, preferred hardware rate, or buffer duration. macOS/offline tests can use unmanaged hooks; deterministic lifecycle tests inject only session operations while retaining the real engine and worker. The app must use one device playback coordinator to own the shared system session.

Pause quiesces the graph and requests preparation suspension before deactivating. After activation has been attempted, Stop and failure cleanup quiesce the graph and finish worker cleanup before deactivation. Deactivation uses [notifyOthersOnDeactivation](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactiveoptions/notifyothersondeactivation) so other interrupted audio can resume. Explicit resume reasserts configuration and activation before starting the retained graph. Duplicate Play while already running, refresh, and preparation retry do not activate output.

Cancellation checks reject stale startup before configuration and before activation is admitted. An admitted activation call cannot be interrupted synchronously; cancellation is checked again afterward, and obsolete startup is cleaned up without starting the graph. Configuration, activation, and engine-start failures retain the original error and use terminal owner cleanup. A later explicit Play can construct a fresh owner.

`audioSessionError` reports a failed deactivation separately from the original playback error. This means cleanup is unconfirmed, not that the system is known to remain active: Apple's [activation documentation](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactive(_:options:)) describes deactivation that can change session state despite reporting an error. Repeated explicit Stop retries unfinished session cleanup without recreating output; successful cleanup clears that diagnostic. A newly successful activation also supersedes the old cleanup error while retaining the obligation to deactivate later. Stopped state describes graph shutdown; it does not certify successful session cleanup. Refresh never retries it, and there is no polling or automatic retry loop.

This is session lifecycle policy, not completed background playback. App controls, the audio background mode, interruptions, route/configuration changes, media-services resets, remote commands, and physical-device validation remain separate work. The low-level `SessionAudioEngine` still leaves session policy to its caller when used without the coordinator.

Five test groups use real offline graphs and preparation workers with injected system calls. They verify lazy setup, exact activation/start ordering, pause/resume, initial and resume failures, separate cleanup errors, and explicit terminal cleanup retries. Deterministic main-queue gates cover Pause/Stop during configuration, Pause/Stop/destruction during activation, and failed cleanup after cancellation without a duplicate automatic attempt. The iOS integration test exercises the actual system adapter, checks its category/mode/options, and renders through pause/resume with preserved position.

Local validation with the pinned Xcode 26.6 toolchain passed all 117 audio tests in 35 suites in both Debug and Release. The focused Thread Sanitizer run passed 35 tests in eight suites with Release optimization and a serialized harness; actual control, preparation, and rendering roles remain concurrent. Nine iOS integration tests, the launch UI test, and the unsigned iOS Release build passed, along with formatting, repository checks, and all 13 CodeQL coverage-guard tests.

All 193 deterministic exports (161 PCM and 32 scalar JSON files) are byte-identical to PR #45. The existing engine, worker, callback, native renderer, planner, sound bank, fixtures, and reference tools are unchanged. Original-reference comparisons were not rerun locally; hosted regression, size, build, and security checks remain separate required results. Simulator/offline evidence does not establish physical-device latency, background reliability, or energy use.
